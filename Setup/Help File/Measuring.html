How Results Are Measured

DiskMark is designed so that the figures reflect the drive rather than the operating system's memory cache.

  • The test writes sequential blocks to a temporary file, wrapping around at the end of the file, for the configured duration; it then reads the file back for the same duration.
  • Throughput is sampled once per second. Average is total bytes divided by total time, not an average of the per-second rates, so a slow stretch is weighted correctly. Min, Max and Last are per-sample rates.
  • IOPS and Latency are averages per block over the whole phase.
  • Writes use unbuffered, write-through I/O unless write caching is allowed, in which case the flush is part of the timed region.
  • Reads are always unbuffered, so they come from the device, not from RAM.
  • The I/O buffer is memory-aligned and filled with incompressible pseudo-random data, so drives that compress or de-duplicate data cannot inflate the results.
  • The space for the test file is reserved before timing starts, so file-system growth is not measured.
  • If the write phase did not fill the whole test file, only the part that was written is read back.
  • Timing uses the high-resolution performance counter.
Tips for meaningful comparisons:
  • Use the same block size, test file size and duration when comparing drives.
  • Close other programs; background disk activity lowers and varies the results.
  • Many SSDs are fast until their internal cache fills. A longer duration and larger test file reveal sustained performance.
  • Results on network drives include the speed of the network connection.
  • Results vary slightly from run to run; repeat the test and compare the averages.
